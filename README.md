# Product Catalog

Create a Flexbox- or Grid-based product catalog in which the product cards are dynamically generated by JavaScript instead of being written manually in HTML. Each card should display the product name, a thumbnail image, and the price. Clicking a card should open a modal that displays a larger version of the image and at least one additional detail for that product.

## Prep

1. Develop a concept for a fictional online store that sells any product(s) you like—shoes, video games, Pokémon cards (or actual Pokémon), foraged mushrooms, freshly baked cookies, whistling lessons, etc.
2. Create and/or collect the following details for **at least eight (8)** different products:
   1. Product name
   2. A high-quality image (stock photo, AI-generated, or your own drawing or photo)
   3. Price
   4. One additional detail of your choosing (e.g., shipping cost or time, color options, longer description, etc.)
3. If needed, use [Squoosh](https://squoosh.app) or your preferred photo-editing tool to resize and compress images according to the IMS322 Docs pages [Coding Style & Requirements](https://ersheff.github.io/IMS322-Docs/style-requirements/#files-and-images) and [Optimizing Images](https://ersheff.github.io/IMS322-Docs/res/optimizing-images/):
   1. `jpeg` or `webp` format
   2. No larger than `3840` pixels in width or `2160` pixels in height
   3. Quality level around 80%
4. Create an `images` folder in your project folder in VS Code, then move the prepared image files to this folder.

## Design Requirements

- The catalog should display approximately 1-4 product cards per row in a responsive layout that adapts to window size. This can be accomplished using either Flexbox or Grid and media queries. The exact number of cards per row will depend on your card design.
- Each product card should clearly display the product name, a thumbnail image, and the price. You may optionally include a subtle hover effect to indicate that the cards are clickable.
- Clicking a product card should open a modal displaying a larger version of the image and any additional product details that were not visible in the catalog layout. You should use the same file for the image, just styled to be larger using CSS.
- The modal should be closable via a close button or by clicking anywhere on the modal.
  - _Hint: You can attach an event listener to the `<dialog>` element itself._
- Apply **at least one (1)** non-default font to the entire page. Ensure the font is either [web safe](https://ersheff.github.io/IMS322-Docs/css/typography/#web-safe-fonts) or imported correctly.
- Use at least **one (1) non-greyscale color** somewhere in your design that relates to the topic (e.g., pulled from photos).
- Add a responsive **documentation section** at the bottom of the page using Flexbox or Grid with the following content:
  - Both versions of the Profile Creator sketch, with captions.
  - Both **unannotated** Profile Creator wireframes (mobile and large), with captions. _Do not include the annotated wireframes._
  - A single reflective paragraph. You may use placeholder text until final submission (see details in [Finishing Up](#finishing-up)).

### Design Recommendations

Although the most of the HTML content will be generated by JavaScript, the structure and styling of the catalog, product cards, and modal should be fully designed with placeholder content that is visible on page load. This allows you to test and refine your design before implementing JavaScript. Remove the placeholder content once your JavaScript is working.

## Technical Requirements

This project simulates dynamically creating page content as if in response to a database query. While a server would usually return a file containing the requested information, here you will write an array of objects with product details directly in your JavaScript file.

Your submission should specifically demonstrate the following in JavaScript:

- Declaring an array
- Populating the array with objects containing product details
- Iterating through the array using a `for` or `for...of` loop (_do not_ use the `forEach()` method)
- Creating HTML elements with `document.createElement()`
- Appending elements using `appendChild()`
- Attaching data to the HTML elements using `dataset`
- Responding to the `event` object in the function called by an event listener

_Do not_ use template literals or manipulate the `innerHTML` property of elements, even if suggested by Chat GPT.

_Example using template literals and innerHTML_

```js
// ❌ Don't do this...

profileCard.innerHTML = `
	<h1>${firstName} ${lastName}</h1>
	<p>${userBio}</p>
	<a>${userSite}</a>
`;
```

### Technical Recommendations

You may create the `<dialog>` element (for the modal) and the catalog container (Flexbox or Grid) manually in HTML and CSS. Only the product cards themselves need to be created and appended using JavaScript.

To streamline styling, try to use CSS nesting by assigning a single class (e.g., `.product-card`) to each card and nesting related styles inside that rule.

_CSS nesting example:_

```css
.product-card {
	h1 {
		/* nested h1 styling */*
	}
	h2 {
		/* nested h2 styling */*
	}
	p {
		/* nested p styling */*
	}
}
```

## General Requirements

**All projects are expected to meet the following criteria.**

### Naming Conventions

- Name `class` and `id` attributes in HTML and CSS using the "kebab-case" convention, where lowercase words are separated by hyphens.
- Name `functions` and `variables` in JavaScript using the "camelCase" convention, where each word (except the first) begins with a capital letter and contains no spaces or hyphens.
- Do not use spaces or special characters in file names other than hyphens `-` or underscores `_`. Rename long or cryptic file names as needed. For example, `dog.jpeg`, not `neom-9E9NsEiUGxg-unsplash.jpeg`.

### Files and Images

- Each project submission must include at minimum an `index.html`, `styles.css`, and `main.js` file. These are provided in the template repository, so do not delete or rename them.
- All images must be in `jpeg` or `webp` format with a resolution no larger than `3840` pixels in width or `2160` pixels in height. Logos, icons, or other vector drawings may be in `svg` format. Use [Squoosh](https://squoosh.app/) or another image editor to resize or compress images before adding them to your project (set quality level around 80%).
- All image files must be stored inside an `images` folder.

### Comments

- Use comments to explain and organize your code. At a minimum, comments should be used to separate code into logical sections.

### HTML

- Do not change the provided `<link>` or `<script>` tags in the `<head>` of `index.html`. These are already configured to correctly load `styles.css` and `main.js`. You may add additional `<link>` or `<script>` tags in the `<head>` if needed (e.g., to load external fonts).
- Do not write any styling or scripting in your HTML. This includes:
  - Inline `style` or event attributes (such as `onclick`)
  - `<style>` tags
  - `<script>` tags outside of the `<head>`
  - `<script>` tags that do not reference a `src` file

### CSS

- All colors should use HEX or RGB values taken directly from wireframe designs. Minor variations are acceptable.
- Always specify font families. If you are not using a "[web safe font](https://fonts.google.com/knowledge/glossary/system_font_web_safe_font)," make sure the font is properly loaded in your project. If you are using a single font family for all elements, apply it globally in the `main` selector.
- Layouts should adapt to any window width from `320px` and above. A default media query breakpoint at `640px` is provided in `styles.css` to make size and layout adjustments as needed for wider windows.

### JavaScript

- Use the keywords `let` or `const` when declaring variables in JavaScript. Do not use `var`.
- Do not use a `DOMContentLoaded` event listener or `window.onload` property. Many online examples may suggest these, but they are unnecessary and may cause conflicts in later projects.
- Do not use the ternary `?` operator for conditionals. This is often suggested in AI-generated code. Use `if` statements instead.

## Submission

It is recommended that you **Stage**, **Commit**, and **Sync** your work often, even before the project is finished.

1. Open the **Source Control** panel in VS Code.
2. Stage all changes by clicking the **+** next to **Changes**.
3. Enter a commit message and click **Commit**.
   - Use "draft" for your draft submission (where applicable).
   - Use "finished" for your final submission.
   - _If you do not use these commit messages, the commit closest to the due date will be used for grading._
4. The **Commit** button will change to **Sync Changes**. Click this to push the latest changes to GitHub. _If you only commit but do not sync, I will not be able to see your work._
5. Open your repository on GitHub.
6. Go to the **Settings** tab for the repository (not your account), then navigate to the **Pages** section.
7. Under **Branch**, select "main" from the dropdown and click **Save**. You only need to publish the site once per project. Any future changes pushed to GitHub will automatically update the live site.
8. After a few moments, refresh the **Settings** page. A GitHub Pages URL should appear near the top next to a **Visit Site** button. Click this button to verify your site loads correctly.
9. Copy the GitHub Pages URL and paste it in the **Website URL** field of the corresponding Canvas assignment, then submit.

## Grading

**38 points**

### Design Requirements

**12 points**

- **Content** (4 points)
  - All required text, elements, inputs, and images are present and of high quality, including the documentation section.
- **Layout and Responsiveness** (4 points)
  - The layout adopts a mobile-first approach and adapts to all window sizes.
- **Color** (2 points)
  - At least one non-greyscale color that relates to the topic is used in the design.
- **Translation** (2 points)
  - The final submission is a faithful translation of the wireframe, including overall layout, font choices, and color scheme.

### Technical Requirements

**14 points**

- **Array** (2 points)
  - An array of objects with product details is declared in JavaScript.
- **For Loop** (2 points)
  - A for or for...of loop is used to iterate through the array.
- **DOM Methods: Element Creation** (2 points)
  - The document.createElement() method is used correctly to create HTML elements for each product card.
- **DOM Methods: Appending** (2 points)
  - The appendChild() method is used correctly to append product cards to the correct container in the document.
- **Modal Implementation** (4 points)
  - A modal with the correct product details opens when a card is clicked.
  - Modal behavior is implemented using the dataset property and event object.
- **Publishing and Submission** (2 points)
  - The page has been published using GitHub Pages, and the correct link was submitted to Canvas.

### General Requirements

**12 points**

These standards and best practices are graded separately from the project-specific design and technical requirements listed above.

- **Naming Conventions** (2 points)
- **Files and Images** (2 points)
- **Comments** (2 points)
- **HTML** (2 points)
- **CSS** (2 points)
